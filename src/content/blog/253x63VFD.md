一 · 初识GP247AI VFD
===============
屏幕到货，将其从厚厚的泡泡纸中取出，可以看见该VFD本体由两部分组成，一部分是VFD真空管，一部分是VFD的控制电路板，主控芯片型号是STC15W4K56S4，控制电路板有五个接口。
1个3P供电口，电压为典型的5V，两个5P的口，尚不清楚具体作用，中部一个串口，用于stc芯片的烧录和外部通信，中部接口作用未知，有未焊接焊盘，暂不对此做研究。

STC芯片中烧录了示例程序，屏幕显示没有问题，不过有个小细节，屏幕上电会有滋滋声，这就是复古的味道啊（赞赏）。

不过我数了一下，纵向应该有64个像素，横向还没数，但我觉得应该不会是253这么奇怪的数字，更像是256个像素，凑成256x64，不知道为什么卖家说是253x63。

二 · 控制电路板研究
===============
> [!WARNING] 警告
> 该驱动板会通过一个 **多级倍压整流升压电路** 将5V升压至将近**90V**（图中的***VHA***），使用时请勿将手触碰VHA和临近的GND，否则会导致手受电击，*虽然不痛*:spoiler[(其实还是有点刺痛)]，但是会吓一跳而且有个小水泡，且如果你的手松掉让VFD被\****Drop it***，将有可能导致VFD碎裂导致真空环境被破坏，这损失可不小。

三 · 驱动文件研究
===============
玩过oled的小伙伴都知道，像oled这样的屏幕是用i2c来通信的，那么像VFD这样的屏幕，肯定也是通过某种方式来通信的。于是我在网络上搜索该VFD芯片模块**GP247AI**，搜索结果比较少，但是发现了一些信息：

1. 一个Github仓库，不过是电路板制造相关文件<br>
::github{repo="StephiB/GP1247AI_PCB"}

2. 一个叫做RS的供货商，其中一款日本双叶电子工业株式会社制造的VFD屏幕的货品，提到了i2c通信，i2c可疑度++<br>
https://www.rsonline.cn/web/p/vfd-displays/1701704

3. 一个在Gitee上对U8G2的移植库，内涵GP1247AI的相关文件<br>
https://gitcode.com/kvcx/OLED_IIC_DMA_Demo/blob/main/U8G2/u8x8_d_gp1247ai.c

4. 商家大哥的原理图，VFD模块的连接部分引出了四根线：<br>
**VCLK时钟** **VCS片选** **VDAT数据** **VRST复位**<br>
可以知道这是一个串行通信接口

5. 另一个PCB制造文件，不过是GP1287AI，<br>
::github{repo="izilzty/GP1287AI_VFD_BOARD"}
但是我在该github仓库找到了另一个仓库<br>
::github{repo="izilzty/u8g2"}
该仓库中的U8G2驱动文件似乎支持GP1247AI！<br>
先保留这个仓库

因此，虽然找不到相关驱动，但是可以认为通信协议是i2c驱动的可能性很大，接下来让我们看看示例文件里的驱动文件

函数*Spi_Send_Byte*：<br>

~~~cpp
void Spi_Send_Byte(unsigned char dat)
{
    unsigned char i;
    for (i = 0; i < 8; i++) {
        VFD_SCK = 0;
        VFD_DAT = dat & 0x01; // LSB first
        VFD_SCK = 1;
        dat     = dat >> 1;
    }
}
~~~
。。。<br>
看来是个LSB的半双工SPI通信协议，好吧破案
